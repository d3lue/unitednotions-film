United Notions Film: how to change the site
Written 7 October 2026, the day the site went live on DreamHost.

THE EDITING PAGE

      https://unitednotions.film/edit/

  It asks for a name and a password. It lists the pages written there; "New page" opens the editor.
  The editor is a form on the left and a preview on the right, which follows as you type:
      Title, Where it goes (Research or News), Date, Place, Summary.
      Content: the HTML of the page. Write it, or paste a whole page: its title, summary, date and place
         fill the fields, its styles and body become the content. Layout and styles are kept as written.
      Pictures and videos: drop the files on the box. They are kept with the page when you save, and are
         named in the content as they are called:  <img src="whale.jpg" alt="...">. "Insert" writes that
         line for you. The first picture of the page is the one shown in the list.
      Spanish version (optional): a title, summary and content in Spanish. Without it the Spanish site
         shows the English.
      The address of the page: made from the first title (small letters, digits, dashes) and fixed after
         that, so links keep working. It can be chosen before the first save.
  "Save" keeps the page in the workshop. "Save and publish" also rebuilds the site: about two minutes later
  the page is live at /research/<address> or /news/<address>, in the sitemap and in the guide for AI assistants.
  "Remove this page" takes it out; the next Publish makes that real.

  The password: a person with SSH access adds names with
      ssh unfweb@iad1-shared-b7-43.dreamhost.com   then   htpasswd ~/unf-workshop/.htpasswd NAME
  The login for the first name, unf, is in ~/unf-workshop/EDIT-LOGIN.txt on the server.

PUTTING THE EDITING PAGE ON THE SERVER (once)

  From this folder on a Mac:
      sh server/install-editing.sh
  It sends the workshop up, puts server/edit/ at /edit/ in the site, and adds one cron line to the server:
  once a minute, if the editing page has left the marker file publish.requested, run server-publish.sh.
  The editing page itself never runs anything; that cron line is what publishes. Without it, "Publish"
  waits for ever. The password file (~/unf-workshop/.htpasswd) is made by hand, as above, and is not
  touched by the script. Run it again whenever server/edit/index.php changes.

WHERE THINGS ARE

  On the server, in /home/unfweb (a user that owns this site and nothing else, so the editing page can reach nothing else):
      unitednotions.film/          the live site, written by the build. Never edit it by hand.
      unitednotions.film/edit/     the editing page
      unf-workshop/                the workshop: the program that writes the pages, and the texts it reads
          build/pages-in/          the pages written on the editing page, one folder each (section.txt says Research or News)
          build/research/en, es    the 30 lab notes of the old site, as tagged text (T:, P:, IMG: ...)
          build/content.py         the works on the home page
          build/content_pages.py   About, People, News, Film Futurism, Press
          build/strings_es.py      the Spanish of everything that is not a lab note
          publish.log              what the last publish said
          server-publish.sh        the publish itself: pictures, build, copy to the live folder, 34 checks
          EDIT-LOGIN.txt           the name and password of the editing page

  The same folder lives on Dan's Mac and on GitHub (github.com/d3lue/unitednotions-film), as copies.
  The server's workshop is the one that counts.

THE OTHER PAGES: WORK, ABOUT, PEOPLE, FILM FUTURISM, NEWS, PRESS

  Their texts are plain sentences in three files: build/content.py (the home page), build/content_pages.py
  (the rest) and build/strings_es.py (the Spanish, keyed by the English sentence). The 30 lab notes of the
  old site are tagged text in build/research/en and es. They are edited in VS Code on a Mac, then
      sh publish.sh
  sends them up and rebuilds the site on the server. Or edit on GitHub and "Run workflow" under Actions.
  Change the words, keep the quotes and the commas. The one trap: if an English sentence changes, its copy
  on the left in strings_es.py must change too, or the Spanish page shows the English for that sentence.

FROM A MAC

      sh publish.sh          brings down what the editing page added, sends up what changed here, builds on the server
      sh publish.sh --down   only brings the server's workshop down, to look or to edit
      sh check.sh            tries 34 addresses of the live site and names any that fails

  The originals of the 28 lab videos are in build/video-in on Dan's Mac (1.2 GB). The server has their web copies.
  Keep the originals somewhere backed up: the old site that streamed them is gone.

WHEN SOMETHING LOOKS WRONG

  The editing page shows the log of the last publish. The last line counts the checks: "passed: 34  failed: 0" is right.
  A page whose folder has no index.html, or whose name has a capital letter or a space, is named in the log and left out.
  If the editing page itself does not answer, the site still does: the two are separate.
